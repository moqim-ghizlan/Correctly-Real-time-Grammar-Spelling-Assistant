## 1. Product decision and acceptance contract

### 1.1 Mission

Translate into (and summarize in) many more languages than the six of
V5.5 (French, English, Arabic, Turkish, German, Spanish), while keeping the
language menus quick to use.

### 1.2 New V5.16 functionality

- **A curated catalog of about 40 languages** that Gemini and OpenAI handle
  well — not "every language": ~7,000 exist and quality falls sharply for
  low-resource ones. Each entry has a stable ID (BCP 47 base code), an
  English name for the AI instruction, a native name, and a writing
  direction.
- **Variants where they matter**, generalizing the V5.5 Arabic variant:
  - Arabic: Modern Standard, Syrian (existing) + Egyptian, Moroccan
    (Darija), Lebanese, Gulf (to confirm, D3);
  - Portuguese: Brazil / Portugal;
  - Chinese: Simplified / Traditional;
  - (optional, D3) Serbian Cyrillic / Latin, Kurdish Kurmanji / Sorani.
- **Right-to-left output** for every RTL language (Arabic, Hebrew, Persian,
  Urdu, Sorani Kurdish…), not only Arabic.
- **Usable menus**: the target menu shows **favorites first** (a group
  "Your languages"), then all languages in alphabetical order of the
  interface language, each as "Name — native name" (e.g. "Japonais —
  日本語"). Favorites are chosen in Settings → Actions → Translation.
- Everywhere a language is chosen: Translation tab, Translate & rewrite,
  Summary tab, the V5.4–V5.5 right-click panel, the 5.15 bubble, settings.
- The **interface stays English/French**: these are languages of the text,
  not of Correctly's UI.

### 1.3 Non-goals

- No automatic "all languages", no free-text language field.
- No translation of Correctly's interface into new languages.
- No change to the prompts' structure, to limits, statistics or sync rules
  (the new preferences ride on the existing `settings` domain).
- No language detection request: "Auto-detect" stays inside the single
  translation request, as today.

## 4. Functional design

- **Catalog** (`shared/translate.ts`): `LANGUAGES` grows; each entry
  `{ id, label, native, rtl }`. New `VARIANTS: Record<LanguageId, {id,
  label, prompt, rtl?}[]>` (only languages with variants have entries);
  `ARABIC_VARIANTS` stays as `VARIANTS.ar` for compatibility.
- **Request** (`TRANSLATE_TEXT`, `SUMMARIZE_TEXT`): the existing `variant`
  field becomes "a variant of the target": valid only when the target has
  variants and the ID belongs to that target, otherwise `null` (exact-shape
  guard updated; old messages stay valid).
- **Instruction**: `Target language: <English name>[ — <variant prompt>]`,
  as today for Arabic; the user's text is never interpolated.
- **RTL**: result elements already use `dir="auto"`; add `dir="rtl"` when
  the chosen target (or variant) is RTL, as Arabic is today in the panel.
- **Menus**: one helper `languageOptions(common, favorites)` returns two
  `<optgroup>`s ("Your languages", "All languages") sorted with
  `Intl.Collator(locale)`; used by every select listed in §2.2.

## 5. Data model and storage

- `correctly.v5.settings.translation` (normalized by `normalizeTranslation`):
  - `source`, `target` (unchanged, now any catalog ID);
  - `variants: Partial<Record<LanguageId, VariantId>>` (new) — the preferred
    variant per language;
  - `favorites: LanguageId[]` (new, ≤ 12, unique, catalog IDs only);
  - `arabicVariant` (5.15) is **read** as `variants.ar` when `variants` is
    absent, and still **written** for one release so a 5.15 computer
    synced with 5.16 keeps its Arabic variant (§7).
- Unknown IDs (e.g. a future language synced from a newer version) fall
  back to the defaults, never crash a menu.

## 6. Messages and security

- No new message. Guards stay exact-shape; IDs only from the allowlist; no
  language name from the page or the model ever reaches the instruction.
- No log; no change to permissions, CSP or hosts.

## 7. Limits, statistics and sync

- Limits and statistics: unchanged (same task kinds).
- Sync (5.14): `translation` is part of the `settings` domain. A 5.15
  computer receiving a 5.16 target it does not know falls back to its
  default (normalization), and keeps `arabicVariant`. Document it in the
  release notes: "update every computer to 5.16".

## 8. User interface (fr/en)

- Language and variant names in `shared/i18n.ts` (English and French) for
  every catalog entry; native names from the catalog.
- Settings → Actions → Translation: "Your languages" (favorites)
  multi-select, with the default target and per-language variants.
- Static texts via `scripts/i18n-options.mjs`.

## 0. Mission, boundaries, priorities, terminology

### 0.1 One-sentence mission

Take the **existing and actually implemented** Correctly V5.1–V5.9 extension; systematically verify and repair its cross-feature integration, security, privacy, quota enforcement, editor safety, accessibility, performance, packaging and documentation; then deliver a **truthfully evidenced, reproducible personal release** without a local backend or Java runtime.

### 0.2 Exact release target

The final artifact is a locally installable **unpacked Chrome/Brave Manifest V3 extension** (and, if practical, a ZIP of the identical extension payload), plus release notes, a test evidence bundle, a security audit, a migration/rollback guide, and an explicit release decision. The owner installs and supplies personal API keys in the extension Settings. **No Correctly-hosted server, cloud proxy, Windows EXE, Windows installer, Java service, Python runtime, LanguageTool daemon, background monitoring server or account system is required.** Build-time tools are different from runtime dependencies: Node/npm and optional test tooling may still be needed by DEVELOPERS.

### 0.3 Explicitly IN scope

1. Verify prerequisites and capture a baseline before modifying code.
2. Fix defects that prevent already-planned V5.1–V5.9 behavior from working or meeting safety contracts.
3. Refactor duplicated logic **only when needed for measured correctness or security**, with strong regression coverage.
4. Add missing regression, integration, browser, migration, accessibility and security tests.
5. Audit API-key storage, provider requests, extension messaging, browser permissions and packaged output.
6. Audit hard caps, alerts and crash recovery, including concurrent tabs.
7. Audit UI text safety, correct selection replacement, undo and custom shortcuts.
8. Audit analytics counting, incomplete tokens/cost display and sanitized export.
9. Measure representative performance, document supported/unsupported sites and prepare personal release artifacts.
10. Provide clear user instructions for API keys, limits, data safety, backups, upgrades and rollback.

### 0.4 Explicitly OUT of scope — stop and ask before changing

- Rebuild V5.1–V5.9 from scratch to conceal missing prerequisites.
- New translation providers, new AI products, subscriptions, payments or account registration.
- Multi-user SaaS backend or distribution of a shared provider credential.
- Any recurring automatic LLM request to analyze everything typed.
- Returning the V4 Java, LanguageTool, Python EXE, tray app or Windows setup as a hidden runtime dependency.
- Replacing Chrome/Brave with another browser as a required platform.
- Syncing personal content, keys or analytics to an external storage service.
- Automatically uploading webpage contents, screenshots, DOM trees, browsing history or the personal shortcut dictionary.
- Claiming that client-only API keys are unextractable, that local quotas guarantee a dollar spending ceiling, or that generated text is always semantically perfect.
- Chrome Web Store publication, code-signing purchases or public marketing, unless separately requested.

### 0.5 Order of priorities when tradeoffs arise

1. **Do not lose, corrupt or silently transmit personal text or secrets.**
2. **No quota bypass, accidental paid calls, automatic hidden retries or silent provider fallback.**
3. **Correctness, recoverability and explicit user consent for text changes.**
4. Reliable preservation of existing V5 capabilities and settings.
5. Browser support and accessibility.
6. Performance and maintenance.
7. Visual polish and cosmetic improvements.

### 0.6 Exact meaning of test statuses

| Status | Meaning | Permitted release claim |
|---|---|---|
| PASS | Test actually executed, objective expected result met, evidence logged | May claim tested for stated environment |
| FAIL | Executed, observable mismatch or regression | Must report bug and gate severity |
| BLOCKED | Could not execute because prerequisite/environment is missing | **Not** equivalent to PASS |
| NOT RUN | Not attempted | **Not** equivalent to PASS |
| N/A | Intentionally irrelevant, with written justification | Must not inflate pass percentage |
| FLAKY | Outcome inconsistent; root cause not resolved | Fail release gate for critical paths |

A specification and a generated test case are NEVER a test execution result. A successful build alone does not prove provider behavior, browser compatibility, data integrity or end-user functionality.

### 0.7 Severity rubric

- **P0 / Blocker:** credentials leaked; personal text silently overwritten/sent; quota bypass; unusable core correction; data-loss migration; remote code injection; potentially chargeable automatic calls; catastrophic build failure.
- **P1 / Critical:** common editor focus/apply failure; wrong operation counted; false $0.00 for unknown billing; failed key isolation; broken Chrome or Brave target; inability to revert after a dangerous mutation; repeated paid calls on retry.
- **P2 / Major:** supported-site workflow inconsistent, major accessibility blocker, weekly period wrong, corrupt-but-recoverable export or misleading warning.
- **P3 / Minor:** wording, layout or non-destructive cosmetic issue with workaround.

**Release condition:** zero open P0/P1; P2 requires owner acceptance with documented impact/workaround and clearly reduced coverage; P3 may be deferred. Do not quietly downgrade severity.

## 2. Expected user experience and final product contract

### 2.1 First launch / new private Chrome profile

1. Install the unpacked extension from the verified build directory.
2. Open its popup or options page; no Java/Windows service is required.
3. Without a key, show a helpful AI-not-configured state; **do not auto-call providers**.
4. Open Providers / API Keys, choose Gemini or OpenAI, enter a personally obtained key in a password-masked input.
5. Select a supported model for Correction, Rewrite and Translation routes, when available.
6. Offer a clearly labeled test action; say whether the test is metadata-only or a **potentially billable generation test** before confirmation.
7. Configure conservative daily/weekly/monthly limits, with clear default behavior and current remaining capacity.
8. Save settings; close/reopen popup and restart browser; configurations persist without exposing raw secret values.
9. Open a normal supported site and trigger Correction on deliberately misspelled text.
10. Show a safe preview; do nothing to the editor until the user chooses Apply.

**Expected:** No pop-up automation, no unexpected charges, no automatic editing, no installation of servers, understandable feedback for missing key or network.

### 2.2 Everyday correction

- User selects a sentence or invokes the defined current-sentence fallback as specified in V5.3.
- Trigger using keyboard, context menu, or smart button; all routes call the **same** correction orchestration.
- The trusted extension component validates site, selection, key route, quota and request intent.
- The model receives only the necessary selected content under user consent; untrusted text cannot override control instructions.
- One provider generation attempt returns structured `no_error` or `corrected` semantics; evaluate the actual defined schema.
- If no errors, display a non-destructive confirmation; **no editor mutation**.
- If errors, display original and corrected text; user can Apply, Copy or Cancel.
- Reject Apply if source text, focus context, selection or DOM/editor state has changed in a way that makes replacement unsafe.
- Safe Undo restores the exact prior value if the required invariant holds.

### 2.3 Multi-style rewriting

- Choose 1–N configured styles; each style is visibly labeled.
- **One generation request** can return several candidates; no separate hidden call per style.
- AI output cannot silently fill fields, be executed as HTML or alter unrelated DOM.
- Applying one candidate updates only the intended text, once; Copy and Cancel never modify it.
- An in-flight result becomes stale if source, target or user intent changes.

### 2.4 Translation / language / dialect

- User chooses source detection/explicit source, a destination language and optional dialect (for example French → natural Syrian colloquial Arabic).
- Preserve names, numbers, negations, instructions and user-protected terms as defined by the translation contract.
- Display target-language and dialect provenance; do not claim guaranteed dialect fluency for every model.
- Do not reinterpret content of an email, code snippet or webpage as a privileged command.
- Keep translation and rewrite request accounting categories distinct and documented.

### 2.5 Personal shortcuts

- A locally stored `bjr`-style trigger expands deterministically on eligible typing boundaries.
- It works offline with no configured API key and does not use generation quotas.
- Import/export, CRUD, disable, rename and conflict resolution preserve historical V4-compatible data only as actually supported by V5 migration code.
- When explicit AI protection is enabled, terms meant to remain unchanged are validated and restored without exposing the entire dictionary to the model.

### 2.6 Limits, warnings, statistics

- User can configure distinct request-count limits for correction, rewrite, translate (and combined task if present) per day/week/month, plus global limits.
- Requests blocked at limits never reach generation transport.
- Warnings at 80%, 95% and 100% are period-aware and deduplicated; 100% produces a visible block.
- Multiple tabs cannot consume the final available slot twice; browser/worker restart cannot create free retries.
- Dashboard distinguishes **attempts**, **successful results**, **previewed candidates**, **applied changes**, **undone changes**, **known token usage** and **estimated cost**.
- Missing usage/price data is marked `Unknown`/`Partial`, **never falsely `$0.00`**.
- History exports contain no API keys, input content, output content, complete browsing URLs or unsafe spreadsheet formulas.

## 4. Formal cross-version invariants — turn each into tests

### 4.1 Product and deployment invariants

- **INV-01:** Production functionality works without Java, LanguageTool, Python or a Correctly local backend process.
- **INV-02:** The extension runs as Manifest V3 in Chrome and Brave on documented supported versions.
- **INV-03:** The compiled extension uses no remotely hosted executable JavaScript or unreviewed runtime code download.
- **INV-04:** No personal credential is bundled in source, generated assets, ZIP, test snapshots or logs.
- **INV-05:** No AI operation is triggered merely by a pause, period or page load; it requires a deliberate action.
- **INV-06:** A missing credential cannot result in an outbound AI generation attempt.
- **INV-07:** The same explicit operation cannot be accidentally dispatched by two trigger handlers.

### 4.2 Text and editor invariants

- **INV-08:** No editor content is modified before explicit Apply or the user's deterministic local-shortcut action.
- **INV-09:** Applying to a stale selection, stale editor or changed source fails safely without mutation.
- **INV-10:** A preview and Copy action never modifies an editor.
- **INV-11:** Cancel is pure, does not generate additional billable requests and retains user text.
- **INV-12:** Undo targets only an owned, still-valid Correctly edit and never reverses unrelated user typing.
- **INV-13:** Sensitive or unsupported editors cannot leak their text into an AI request.
- **INV-14:** IME composition, RTL, Unicode combining characters and emoji do not cause offset corruption.
- **INV-15:** Unsupported rich editors fail with a useful message, not a guessed DOM replacement.

### 4.3 Network, provider, and credentials

- **INV-16:** Raw API keys remain in trusted extension execution contexts; no content-script/page direct access via storage or messaging.
- **INV-17:** A webpage cannot send a forged message causing arbitrary provider requests or credential reads.
- **INV-18:** A provider route is explicit and stable for an admitted operation; no silent paid fallback.
- **INV-19:** One user action and one chosen multi-style operation produces one provider **generation** attempt unless the user expressly retries.
- **INV-20:** A network timeout after possible dispatch never triggers an automatic chargeable retry.
- **INV-21:** Model output is treated as untrusted data, never HTML/JS or instructions to execute.
- **INV-22:** Every remote operation has bounded request size, response size, timeout, schema validation and safe errors.
- **INV-23:** Usage metadata missing/ambiguous is recorded as unknown, not fabricated.

### 4.4 Quotas and warnings

- **INV-24:** **Every** potentially billable generation transport path requires valid V5.8 admission.
- **INV-25:** Aggregate active reservation + possibly-sent usage never exceeds configured caps at admission time.
- **INV-26:** Switching key/provider/model cannot reset a global cap.
- **INV-27:** Worker crash or browser restart cannot cause automatic resends/free retries.
- **INV-28:** Blocked pre-send requests never reach a generation endpoint.
- **INV-29:** Potentially sent uncertain attempts remain conservatively counted.
- **INV-30:** Alerts at 80/95/100% are correctly crossed, deduplicated and accessible.
- **INV-31:** Local quota is never described as a guaranteed API invoice or provider spend cap.
- **INV-32:** Local shortcuts do not count against AI request quotas.

### 4.5 Analytics, data and release invariants

- **INV-33:** Attempt counts are never confused with applied corrections or number of generated style variants.
- **INV-34:** Analytics reads, clearing, export or pricing edits can never change active quota admission state.
- **INV-35:** Unknown cost/usage has an explicit unknown/partial state, not fake zero.
- **INV-36:** Export cannot contain source text, model output, API keys, sensitive selectors or full browser URLs.
- **INV-37:** Migration is versioned, idempotent and non-destructive to profiles, settings, quotas and shortcuts.
- **INV-38:** Current user settings survive browser/worker restart and compatible upgrade.
- **INV-39:** Storage unavailable/corrupt never becomes an implicit unlimited-generation authorization.
- **INV-40:** Browser and build artifacts are examined independently of unit test success.
- **INV-41:** Tests and report labels are truthful and evidence-bearing.
- **INV-42:** Personal release documentation accurately states key exposure, sent-text privacy and cost uncertainties.
- **INV-43:** Browser local profile scope is disclosed; uninstalling may delete local extension data and upgrades must preserve the extension ID when feasible.
- **INV-44:** Regression fixes do not weaken earlier milestones' allowed-editor and explicit-action guards.
- **INV-45:** No P0/P1 issue is open at release; any N/A/P2 waiver is justified by the owner.

## 5. Work-package execution sequence and exact completion gates

**Rule:** The agent follows WP-00 through WP-14 sequentially. Every WP must end with: touched files; decisions; commands/tests run; actual results; deviations; open risks; and evidence paths. Use a dedicated working branch and small reviewable commits **only with owner permission**. Never force-push or destructively rewrite branch history.

### WP-00 — Freeze scope and collect baseline

1. Read the entire V5.10 spec and prerequisite files; write a one-page feature contract.
2. Record branch, HEAD, dirty status, package scripts and browser versions.
3. Run current build and tests without changing source first.
4. Inventory every permission, storage store, model adapter and external URL.
5. Produce `docs/v5.10/00-baseline.md` (illustrative path; adapt to repository) with exact failures.
6. **Gate:** credible map of actual code and prerequisites exists. If not, STOP.

### WP-01 — Static security and trust-boundary audit

1. Read runtime entry points and message handlers.
2. Map credentials from options entry to storage to service-worker transport; locate all reads/writes.
3. Prove content scripts and page DOM never receive raw credentials.
4. Check untrusted message origins and strict schema/type/length validation.
5. Search for `eval`, `new Function`, remote scripts, dynamic script loading, `innerHTML` with user content, broad host permissions, leaks in errors/logs.
6. Inspect bundled JS and source maps; secret scanning must include `dist/`, archives and test fixtures.
7. Propose minimal fixes and add exploit regression tests.
8. **Gate:** no known credential or arbitrary-provider exfil path before live tests.

### WP-02 — Provider transport and paid-request lifecycle

1. Trace Correction, Rewrite, Translation and optional generation test through the same centralized trusted dispatcher.
2. Assert operation ID created once, route frozen, quota reservation committed, send marked before network dispatch.
3. Validate each provider's current request and usage response shape against official documentation at execution time.
4. Unit-test HTTP 401, 403, 404, 408, 413, 429, 5xx, network offline, abort, bad JSON, malformed model output and unexpected empty response.
5. Eliminate implicit auto-retry and silent provider fallback.
6. **Gate:** every remotely billable generation path has pre-send quota authorization and deterministic accounting.

### WP-03 — Quota datastore, race and restart hardening

1. Inspect V5.8 authoritative IndexedDB or actual transactional store, version and migration gates.
2. Verify atomic admission across tabs and scopes; do not replace it with naive `chrome.storage.local` read-modify-write.
3. Simulate two simultaneous dispatches with one slot remaining.
4. Kill worker before send, after permit, during fetch, after response, during settlement; verify conservative recovery.
5. Audit timezone/DST, thresholds, resets and policy changes while calls are in flight.
6. Document the difference between **local attempt limits** and actual spending caps.
7. **Gate:** zero concurrency or restart bypass; storage error fails closed.

### WP-04 — Original-text ownership, transaction and undo

1. Audit eligible editor types and prohibited ones.
2. Ensure keyboard, right-click and smart button share a single source-selection snapshot contract.
3. Simulate source mutation while provider is running; Apply must refuse stale output.
4. Test `textarea`, text inputs, supported simple contenteditable, selection direction, cursor changes, focus theft, undo and copy.
5. Verify IME, RTL, emoji and surrogate pair selection boundaries.
6. **Gate:** zero unintended mutation; complex unsupported editor behavior clearly signaled.

### WP-05 — Correction, rewrite, translation and custom shortcuts integration

1. Verify one-request correction contract: `no_error` vs `corrected` without an extra yes/no call.
2. Verify multiple rewrite styles produce labeled candidates from ONE generation request.
3. Check faithful French/English grammar behavior and quality fixtures (not just schema).
4. Verify language/target/dialect controls: French→Syrian Arabic and vice versa; avoid silently normalizing to MSA.
5. Verify shortcut expansions remain deterministic, offline and zero-token; test protected terms across all AI tasks.
6. Test importing old shortcut data as a preview/transaction, not overwriting it on parse errors.
7. **Gate:** all core tasks work together, no regressions in saved text.

### WP-06 — Storage migrations, corruption and backup

1. Identify every persisted schema/version and current migration chain.
2. Create sanitized fixtures for fresh profile, each previous supported version, partially migrated profile and malformed settings.
3. Migrate one version at a time with logged dry-run results; verify idempotence on rerun.
4. Verify credential profiles, routing preferences, shortcut entries, caps, timezone, warnings, history and display preferences survive.
5. Check extension ID continuity and upgrade behavior; document limitation when ID changes.
6. Test safe restore from export and ensure no secret exported.
7. **Gate:** no undetected data loss; corrupt state never grants unlimited generation.

### WP-07 — Statistics and cost consistency audit

1. Verify attempt journal is source of truth; projections may be rebuilt without altering quotas.
2. Reconcile global and per-task counts from known fixtures; never sum overlapping groups as distinct attempts.
3. Verify Apply/Copy/Cancel/Undo tracking reflects actual actions, not model candidates.
4. Test Today/Week/Month/Custom, DST, different timezones and timestamps around midnight.
5. Test provider token metadata absent, zero, partial, cached/reasoning classes, and changed historical pricing.
6. Ensure all cost figures are labeled estimated/partial; never silently assume a known price for unknown model/date.
7. Test CSV formula injection, JSON export and clear-history separation from quota state.
8. **Gate:** analytics is faithful and cannot mutate enforcement.

### WP-08 — UI, accessibility, localization and UX polish

1. Test popup, options, context menu, editing popover, style picker, translator and dashboard at narrow/zoomed sizes.
2. Ensure reachable keyboard focus, sensible tab order, visible focus, Esc close behavior and screen-reader labels.

## 6. Build, dependency and Manifest V3 hardening

### 6.1 Manifest and permission review, precise checklist

- `manifest_version` is `3`; all referenced files exist in the production artifact.
- Background service worker entry is valid and actually loads after installation.
- Host permissions are limited to configured provider endpoints or a clearly documented minimum; avoid wildcard `https://*/*` simply for convenience.
- Content-script match patterns are no wider than intended. Avoid injecting into pages where the extension should never collect content.
- `web_accessible_resources` exposes **no** API keys, private state, test fixtures, or debug endpoints; ideally only explicitly needed static assets.
- `externally_connectable` is absent unless necessary, and if present tightly restricted.
- Content Security Policy does not allow broad execution of arbitrary remote JS or unsafe evaluation.
- Any context menu, commands, storage, notifications, tabs or scripting permissions are justified by a real feature and tested.
- Restricted browser pages produce a graceful message; never attempt hidden privilege escalation.
- Extra broad permissions introduced during development are removed before release.
- Browser action icons exist for stated sizes; broken icons never prevent core functionality.

### 6.2 Build hygiene

- Use committed dependency lockfile and repository-defined scripts; never inject latest package versions without review.
- Do not bundle `.env`, `.git`, vendor source trees, private keys, user datasets or local debug dumps.
- Ensure reproducible generated manifest from build script; compare to reviewed manifest.
- Verify MIME/module format when `type: "module"` or service-worker bundling is used; test both target browsers.
- Check for removed V4 launcher, local port `8081`, LanguageTool or `javaw.exe` in runtime references; historical documentation references are fine.
- Avoid declaring build-time Node/npm as a prerequisite for the owner simply to use the installed extension.
- Do not assert browser-store compliance without a separate store-policy review; personal unpacked installation is the target.

### 6.3 No forced semantic-version guesswork

The shorthand **V5.10** is a milestone label; a semantic-version tag might be `v5.10.0`, but use the repository's verified versioning strategy. Do not treat `5.10` as decimal `5.1`. Update manifest/build metadata coherently, keep human-readable release notes and ensure previously installed extension profiles can upgrade without data loss.

## 7. Threat model, API-key protection and request authorization

### 7.1 Trust zones (trace real code)

1. **Webpage:** untrusted scripts, DOM, selection, URLs, injected text, page events; never trusted to authorize AI work.
2. **Content script:** extension code in a hostile page environment; may read eligible field text but **must not hold provider API keys**; treat all inbound page content as untrusted.
3. **Extension popup/options:** trusted extension UI, but all user inputs and imported files must be validated.
4. **MV3 service worker:** trusted credential access and single logical dispatcher; lifecycle is ephemeral.
5. **Local persistence:** browser extension storage and authoritative quota journal; integrity and access must be verified.
6. **Gemini/OpenAI HTTPS endpoints:** third-party services receiving explicit text and key. Read provider's latest privacy terms before release.
7. **Browser profile / OS:** owner-controlled but secrets can be extracted by local malware, browser extension compromise or profile access; do not claim magical encryption.

### 7.2 Exact API-key safeguards

1. Never hardcode personal keys in source, settings defaults, tests, demo recordings or release artifacts.
2. Key input remains masked; revealed only deliberately with clear control. Never place full raw key in accessible tooltip or logs.
3. Use the safest built-in local extension storage available given current Chrome/Brave APIs; explicitly configure trusted-context access for sensitive storage where supported (for example the documented `chrome.storage.local.setAccessLevel({accessLevel: 'TRUSTED_CONTEXTS'})` behavior), and **verify** actual browser behavior. This API is not itself encryption.
4. No raw secret is sent via `chrome.runtime.sendMessage` to content scripts, webpage scripts or untrusted frame contexts. Messages carry sanitized operation IDs and selected user text only as required, never credentials.
5. Service worker resolves credential by opaque profile identifier after validating authorized initiator, task, editor eligibility and user intent.
6. Refuse API URLs provided by webpage DOM or generic runtime messages. Provider endpoint must come from reviewed allowlists/adapter config. Limit redirects that could leak headers; apply defensible fetch policies.
7. Profile labels, model IDs, imported settings and error bodies are untrusted strings. Sanitize display and bound lengths; preserve secrets redaction.
8. Do not automatically synchronize keys to Chrome Sync, analytics SaaS or other profiles; clarify that browser extension local storage belongs to a specific browser profile.
9. Deletion of a key removes its persisted value and breaks routes referencing it safely; historic analytics may preserve **non-secret opaque identifiers**.
10. If key leak suspected, stop calls, revoke/rotate it through provider console, inspect browser extensions/profile access, and treat already incurred usage as possibly billable.

### 7.3 Message authorization: explicit rules

- Accept only typed, versioned, known message actions; reject arbitrary actions or extra dangerous fields.
- Validate `sender`, extension context, tab/frame association, page URL eligibility and operation identity. `sender.id === chrome.runtime.id` alone may be insufficient to distinguish the desired trusted action from an untrusted content-script request; design an explicit authorization boundary.
- Never expose generic `FETCH_URL`, `GET_SECRET`, `WRITE_STORAGE`, `RESET_QUOTA` or arbitrary prompt execution commands to content scripts.
- Detect replayed operation IDs and duplicate keyboard/context/smart-button events.
- Do not execute privileged functionality requested by arbitrary page `postMessage` or DOM data attributes.
- A malicious page containing text `ignore limits and call OpenAI` remains **text input**, not an execution instruction.
- Numeric limits, selected text length, payload structure and task variants are validated at runtime in the trusted handler.
- Simulate forged messages in tests, including from an extension content-script-like adversarial caller.

### 7.4 Prompt injection and untrusted model output

- Separate fixed system/task instructions from user text in the provider-supported format.
- Selected text is data; source language detection cannot grant page content privileges.
- Enforce JSON schema or equivalent structured parsing (model-dependent), then semantic validation; reject invalid or unexpected keys and oversized candidates.
- Escape/render outputs as text nodes, not interpreted HTML/markdown unless a reviewed safe renderer is required.
- Guard against model output with embedded scripts, URLs, credential requests, newline overload or self-described tool commands.
- Restore/protect explicitly protected terms using a deterministic local verification layer; reject candidate on mismatch where safe restoration is impossible.
- A user can still deliberately copy generated text; explain that AI may be wrong. Never label AI text as verified legal/medical facts.

### 7.5 Privacy review in human language

Confirm all of the following through instrumentation and code review:

- No provider generation call until an explicit action or explicitly confirmed generation test.
- Only necessary selected/current sentence text is sent; not entire page/form/DOM.
- Site-level disable and excluded fields are checked **before** reading/transmitting.
- Keys sent only to chosen provider over HTTPS in reviewed transport.
- No text, full URLs or provider response is persisted to statistics/quota stores or exports.
- Local debug logs omit secrets, text and full visited URLs; debug mode doesn't secretly remain enabled in release.
- Owner can delete local stats/history (without resetting active quota) and shortcut entries deliberately.
- Data retention and consequences of uninstall/profile deletion are disclosed.

## 8. LLM/provider integration, prompts, output validation and fail-safety

### 8.1 Provider-neutral request life cycle — mandatory order

```text
User explicitly triggers task
  -> identify eligible editor and capture immutable source fingerprint
  -> validate action and required parameters
  -> resolve frozen provider profile/model/task route
  -> ensure credential exists in trusted context
  -> ensure sensitive-site and user-consent checks pass
  -> validate token/text/size limits and proposed generation test class
  -> atomically RESERVE V5.8 quota (every applicable window/scope)
  -> revalidate route/selection/applicable limits, commit POSSIBLY_SENT
  -> exactly one HTTPS generation attempt by chosen adapter
  -> parse and validate provider response + usage metadata
  -> settle attempt, reconcile analytics without mutating quota
  -> show result safely, requiring explicit Apply to modify source
  -> audit/copy/undo event without creating an extra generation attempt
```

This is a conceptual flow; match exact V5.8 state transitions and preserve their transactional guarantees. For cases where the original editor snapshot becomes stale after provider send, discard/disable Apply but retain conservative request accounting.

### 8.2 Provider quality and functional regression

Use a curated, reviewed set of short, medium and long, French/English sentences with fixed expected **constraints**, not an expectation that every LLM produces character-identical output. Validate preservation of numbers, names, negation, dates, URLs, code, meaning and explicitly protected placeholders. For style/translation quality, have the owner review representative examples. An automated schema pass is not proof of language correctness.

### 8.3 Fake transport vs real-provider verification

- **Fake transport default:** deterministic adapter tests and browser E2E run against captured sanitized fixtures or a fully controlled mock. No personal API key or unexpected billing.
- **Live smoke opt-in:** owner-provided key and explicit permission; warn if generation tests may cost money. Use minimum short non-sensitive text, low output cap, pre-set local quota, and stop after agreed bounded calls.
- Never run stress/retry loops against paid endpoints.
- A real 401 means test failed; do not paper over failure by switching provider or overwriting the key.
- Provider documentation/price/usage behavior changes; check latest official docs before making promises about model availability or cost.

### 8.4 Error path contract

| Event | Expected behavior |
|---|---|
| Missing key/model/route | Pre-send validation error; no attempt; no text mutation |
| Selected text empty or prohibited | Pre-send stop; no attempt |
| Active cap at max | Block before network, show which cap and next window |
| Timeout BEFORE provably sending | Release reservation only under V5.8's safe proof conditions |
| Timeout AFTER possible send | Count conservatively; no silent retry; show billing uncertainty |
| 401/403 | Redacted authentication/permission failure; do not reveal key |
| 429 | Explain provider-side rate limit; no circumventing local cap or auto-fallback |
| 5xx | Report transient provider failure; optional *user-confirmed* retry only |
| Invalid provider JSON/shape | No unsafe Apply; record attempt and parse failure |
| Valid response but no usage fields | Show success + `usage unknown`; no invented token/cost zero |
| Source text changed during request | Preview may display, Apply disabled with reason; Copy safe |
| User closes popup/tab | Never resend automatically; state conservatively recovered |

## 9. Quotas, alerts, concurrency and billing uncertainty

### 9.1 Formal counting — inherited V5.8, do not reinterpret

- A potentially billable **generation attempt** is counted at most once per operation ID, subject to authoritative state transitions.
- A correction request = one generation attempt; a 4-style rewrite in one call = one attempt (not four).
- A combined translate+rewrite in one request = one attempt in its documented task category.
- Local shortcut expansion and purely local read/export/UI interactions = zero generation attempts.
- Metadata-only model listing may involve a network call but is not modeled as a generation attempt; do not assume provider policy or billing is universally zero without checking.
- User-confirmed test **generation** = one attempt with documented global/provider/profile restrictions.
- Possibly-sent failed/uncertain attempts remain counted; successful model response is a separate metric.
- An intentional paid retry after an ambiguous failure is **another potentially billable attempt**, and the UI must explain it.

### 9.2 Required limits, intersection and windows

1. Global daily, weekly and monthly caps.
2. Per-task daily, weekly and monthly caps (Correction, Rewrite, Translation, and supported combined task if distinct).
3. Provider and profile caps if implemented in V5.8, never weaker than global caps.
4. **All applicable caps must admit the attempt; the strictest cap wins.**
5. A change of model/provider/profile must not refresh global usage.
6. Use calendar windows in the configured timezone: local calendar day, ISO-week, local calendar month; accurately handle DST and new year.
7. Caps are non-negative validated safe integers according to V5.8 schema; corrupted values fail safely.
8. Admission must atomically check and reserve all relevant scopes; no last-slot race.

### 9.3 Threshold and dedup semantics

- Crossings: 80%, 95%, 100% by integer-safe math; no duplicate toast every render.
- Example 5,000: 4,000, 4,750, 5,000 counted attempts.
- Alerts trigger on **counted possibly-sent** attempts, not temporary reservations later rolled back.
- Several thresholds crossed in one operation: show highest severity and mark lower ones appropriately according to V5.8 rules.
- One exhausted cap blocks, and UI names period/scope/reset time without pretending an exact provider-side billing reset.
- No browser notification permission? In-app state must still be informative; native notifications are optional/opt-in where supported.

### 9.4 Crash/recovery matrix to run

1. Kill service worker before reserving: no hidden quota change.
2. Kill after reservation but before proven network send: recover state safely, avoiding both free retries and stranded capacity according to proven events.
3. Kill at dispatch boundary: conservatively possibly-sent and counted.
4. Kill after provider response but before settlement: no duplicate replay; reconcile ledger truthfully.
5. Kill during alert outbox delivery: no duplicate spam, and 100% cap still visible.
6. Shut browser with two tabs racing for last slot: on restart, ledger and cap unchanged except valid counted attempts.
7. Disk full / IndexedDB unavailable: fail closed for AI generation, keep non-AI shortcuts functional if safe.

### 9.5 Billing honesty

A request-count limit is **not** a guaranteed monetary budget. Providers may count input/output/reasoning/cached tokens differently, pricing changes over time, failed requests may be billable, and token metadata may be absent. The owner should also configure any relevant **provider-side budget/alerts** available in their billing account, understanding provider enforcement may lag. Do not promise automatic API-key revocation at a fixed euro amount unless officially implemented and proven at provider level.

## 10. Statistics, history, pricing and privacy-preserving exports

### 10.1 Inherited V5.9 data integrity

- One physical/potential provider dispatch is one counted attempt ID; grouping by provider, model, profile, task, week and month must not double-count the base number.
- `Successful response` is not `Applied correction`; rejected/unused previews remain separate.

- Mark dollars as **estimated USD**, never invoice-equivalent; avoid false exact conversion to euros without current exchange rate.
- Never display unknown-cost cases as `$0.00`.

1. Today, This Week, This Month and Custom Range.

## 11. Text editing, triggers, undo and site compatibility

### 11.1 Supported vs unsupported editors — validate actual contracts

Supported as actually implemented/tested: ordinary text `input`, `textarea`, and safe simple contenteditables. Do not assume all complex editors (React-controlled editors, rich composer frameworks, Gmail/WhatsApp/ChatGPT internal editors, code editors, closed Shadow DOM, cross-origin iframes) support reliable injection. In complex structures, prefer **read-only preview and Copy** with an explicit unsupported-apply message over a risky replacement.

### 11.2 All three triggers share one engine

1. Keyboard shortcut: not intercepted on ineligible pages or while IME composing; avoid conflicts with browser/OS shortcuts and give a customization/help path if supported.
2. Context menu: use selected text; ignore empty and stale selection; avoid accidentally using text from a different tab/frame.
3. Contextual smart button: unobtrusive, appears only for eligible editors with correct focus; keyboard accessible or alternative always available.
4. All routes produce same source snapshot and call one dispatcher; duplicate fast clicks are debounced/idempotent, not counted twice unless deliberately separate requests.

### 11.3 Safe apply protocol

- Capture editor identity, source text fingerprint, original range, selection metadata and context before generating.
- Reconfirm editor still exists, source segment matches, range is valid, focus/selection policy is satisfied and no IME composition is active.
- Apply exactly one chosen candidate using editor-specific safe mutation path; emit appropriate input events if supported by the framework.
- If any precondition fails, block Apply and offer Copy; **never** replace the first matching string elsewhere as fallback.
- Undo only a tracked and still-valid edit; if subsequent unrelated typing occurred, refuse stale custom undo gracefully.
- Clipboard failure is visible and does not mutate source.

### 11.4 Site classification and tests

- **Local fixture page:** safe plain `textarea`, text input, simple contenteditable, complex nested contenteditable, readonly, password, email/url/tel/search, code editor simulator, IME field.
- **Public normal site:** test keyboard/right-click/button with dummy text, avoiding personal data.
- **Gmail / ChatGPT / WhatsApp Web / LinkedIn / Reddit:** use test accounts or safe non-sensitive drafts where permitted; record supported actions and explicit limitations. Never claim compatibility from loading alone.
- **Restricted browser pages:** chrome://, browser store, browser-internal pages; expected graceful limitation.
- **Iframes/shadow roots:** only as permitted and actually implemented; test known open Shadow DOM support and block unsafe contexts.

## 13. Storage schema, migrations, backup and data integrity

### 13.1 First map every persistent object

Inspect and document: provider profiles/keys, routing, model capabilities, global and task caps, timezone and alert preferences, authoritative attempt journal, active reservation state, alert dedup state, statistics facts/projections, price versions, shortcuts, import metadata, disabled domains, UI preferences and in-progress preview state if any. ## 16. Real Chrome/Brave end-to-end verification protocol

### 16.1 Before beginning browser tests

1. Build once; record hash of output and manifest.
2. Create **separate new Chrome and Brave profiles**; avoid real browsing accounts.
3. Install the unpacked candidate using each browser's `chrome://extensions` developer-mode flow (Brave equivalent URL when supported).
4. Open extension details and check granted permissions exactly.
5. Open service worker console; watch for startup and unhandled exceptions without logging personal text or keys.

## 19. Troubleshooting playbook — do not randomly patch until root cause is demonstrated

**For each defect:** reproduce on isolated profile → record minimal safe steps → inspect source and state transition → make smallest safe fix → add regression test → run affected and broader suites → retest compiled artifact → record evidence. Do not destroy private user data to force a green test.

| Symptom | Likely causes to investigate | Corrective action / proof |
|---|---|---|
| Extension will not load | manifest path, missing built worker, invalid CSP, bundler output | inspect manifest and browser extension errors; rebuild; install identical output |
| Service worker immediately exits | unsupported browser API, unhandled exception, module loading | reproduce with worker console; remove startup unhandled rejection; check fresh profile |
| Gemini key seems saved but API fails | route/model, key restricted, malformed request, permission | redacted response status + provider doc; test metadata-only where possible; no fallback |
| OpenAI key produces 401 | invalid/revoked key, header mismatch | verify Authorization in trusted adapter; rotate test key; no secret logs |
| User key visible in page | content-script storage access, message forwarding, DOM debug | restrict access/bridge; automated hostile page proves exclusion |
| Browser warns overbroad permissions | wildcard host/content matches | minimize manifest declarations and retest workflows |
| Normal typing incurs generation calls | automatic listener accidentally dispatches | trace action source; hard gate explicit intent; network spy must stay 0 |
| Double charge on keyboard trigger | duplicate listeners, retried handler, race | single operation ID/idempotency and physical dispatch assertions |
| Context menu grabs wrong tab text | stale selection/frame capture | bind operation to sender tab/frame and immutable snapshot; stale guard |
| Smart button covers editor | layout/positioning/z-index | reposition and test zoom/small widths; do not hijack typing |
| Correctly overwrites newer text | stale range/apply guard missing | compare original fingerprint/range; refuse Apply; add reproducer |
| Cursor jumps after Apply | incomplete editor transaction and selection restore | use safe editor adapter, update selection/events, supported-editor testing |
| Undo erases unrelated typing | stale edit owned state | restrict Undo to still-valid own edit, otherwise refuse |
| Emoji or Arabic becomes corrupted | UTF-16 offset vs code points, normalization | grapheme/selection fixtures and transaction tests |
| IME triggers premature expansion | composition events not respected | suppress expansion during composition and test real IME |
| Rewrite generated four calls | per-style loop dispatching | batch styles into one prompt; transport counter asserts one |
| Prompt injection changes routing | model or selected text controls privileged fields | keep routing in trusted code; validate outputs as data |
| Syrian dialect output becomes MSA | loose instruction/unsupported model quality | inspect prompt, test dialect fixtures; human review; avoid unsupported guarantee |
| Protected shortcut term changed | masking/restoration mismatch | local placeholder validation; reject candidate on unsafe mismatch |
| Imported shortcuts disappear | destructive migration/merge policy | dry run and backup; validated atomic merge, idempotent fixture |
| Two options tabs overwrite each other | unsynchronized storage write | serialized mutation/version check, conflict UX; test two windows |
| Quota exceeded by two tabs | non-atomic check/commit | use authoritative transactional admission; last-slot race tests |
| Quota resets on model switch | route-scoped count used as global | keep global independent ledger; model-switch regression |
| Limit reached but generation sent | unchecked adapter direct fetch path | central dispatcher authorization; fail closed; spy physical requests |
| Reservation stuck after crash | missing state recovery | follow V5.8 conservative states, no free potentially-sent refund |
| Failed provider call counted | possibly-sent attempt rule | keep counted; explain billing uncertainty; do not silently refund |
| Warning repeats on every popup open | unstable dedup identity | persist period/scope/threshold ID; check 80/95/100 fixtures |
| Warning missing after restart | outbox not persisted/delivered | durable outbox + bounded recovery without spam |
| Week totals inconsistent | Sunday vs ISO Monday or timezone | inspect period key; test ISO year rollover and DST |
| Dashboard total larger than ledger | double-counting group projections | distinct attempt IDs; reconcile authoritative journal |
| Dashboard says $0.00 with missing usage | unknown coerced to zero | introduce explicit coverage status; retest fixtures |
| Price changes rewrite past cost | current rate applied to all history | effective-dated pricing; no silent historical mutation |
| CSV opens with unexpected formula | unescaped leading `=,+,-,@` | CSV injection neutralization and spreadsheet-safe fixture |
| Export leaks email text | improper analytics metadata payload | remove sensitive fields at source, purge test data, run exfil assertion |
| Clear history resets quota | shared store erroneously deleted | separate analytics and admission stores; exhausted-cap test |
| Quota store unavailable but call proceeds | catch default `allow` | fail closed on IDB/open/transaction errors |
| Popup shows infinite spinner | unresolved promise/worker response | bounded timeout, safe message, clear loading state |
| Invalid model forces fallback | hidden route failover | show explicit choice/confirmation; no silent paid alternate |
| Browser restart repeats calls | queued retry or optimistic state | forbid auto-replay after possibly-sent; recovery fixture |
| Extension update deletes all data | extension ID change/schema bug | ID-stable upgrade + migration backup; reproducible test |
| Chrome works but Brave fails | permission/CSP/worker API differences | browser-specific probe and feature detection; fix or document NO-GO |
| DevTools logs entire prompt | verbose diagnostics | remove/redact logging and recheck compiled code |
| Build only succeeds with Java running | V4 runtime coupling left behind | delete runtime dependency safely and test clean browser/PC |
| Package contains test key | build/env injection | revoke key, remove artifacts, secret scan, regenerate candidate |
| App becomes slow on large history | unbounded scans/joins | indexed bounded queries, pagination/aggregation, benchmark |

**A fix is not complete until its failure reproducer passes AND the relevant neighboring subsystem regression tests still pass.**

## 21. Rollback, recovery, incidents and post-release checks

### 21.1 Rollback principles

- Before upgrade, owner exports personal shortcuts and other safe supported data; API keys may require manual re-entry if secret export is intentionally prohibited.
- Preserve the last known-good extension build and matching schema compatibility note.

- For a failed upgrade, prefer restoring a saved compatible profile/backup in isolation or using the previous known-good build without destructive cleanup.

### 21.2 Incident categories and first actions

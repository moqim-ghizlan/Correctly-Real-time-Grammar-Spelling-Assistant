## Gaps against V5.8

- **One period only.** Weekly and monthly limits, per-action, per-provider
  and per-key limits did not exist.
- **Not an atomic multi-scope store.** The usage record kept only today:
  older days were discarded.
- **No threshold warnings, no pause, and no clock or timezone rules.** The
  day was `localDate()` of the browser.
- **Migration hazard.** V5.7 kept only today's count, so earlier days of the
  week and month are unknown. They cannot be reconstructed.

## Decision: storage

The V5.8 ledger is an **IndexedDB database `correctly-v5-quota`** in the
extension origin. Web pages and content scripts cannot open it.

- **One transaction per decision.** Every decision runs in one `readwrite`
  transaction over all the stores it touches: policy, counters, operations,
  alerts and meta.
- **No new permission.** IndexedDB needs none.
- **Test engine.** Tests use `fake-indexeddb` 6.2.5 (dev dependency only). It
  implements the W3C transaction and auto-commit semantics, so real races
  between several connections are exercised.

`chrome.storage.local` with a promise queue was rejected:

- the spec does not accept it as proof;
- it cannot span several keys atomically while the options page also writes.

## Requirements not fully met (reported, not hidden)

- **Native browser notifications.** Not implemented: they would need the
  `notifications` permission. In-app warnings cover the requirement.
- **Popup glance view.** Correctly has no popup (the toolbar button acts
  directly). The settings page is the glance view.
- **Model-specific caps.** Deferred (optional in the spec).
- **Earlier weekly and monthly usage.** The upgrade cannot recover days before
  the upgrade, because V5.7 never kept them.

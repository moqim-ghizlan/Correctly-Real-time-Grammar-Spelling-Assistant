### Credential storage and access boundary

- Keys are only in `correctly.v5.secrets`, written with their profile in a
  single storage call and read back.
- The options page renders metadata only (`loadProfiles` never reads
  secrets). Key fields are password inputs, cleared after saving and never
  refilled.
- Messages carry a route slot or profile ID, never a key.
- `chrome.storage.local` is restricted to `TRUSTED_CONTEXTS`.
- Content scripts receive only `PAGE_CONFIG` (smart button and enabled
  shortcuts).

### Routes

- A task route wins over the default.
- A task set to "Use the default route" inherits the default.
- A route to a deleted, disabled, revision-mismatched or wrong-provider
  profile blocks the request and never falls back.
- Changing the provider in the route editor clears the model.

### In-flight policy

- A route change affects the next request only.
- Deleting a profile, or replacing its key, aborts the running request
  locally (`ROUTE_CHANGED`, "may still be billed").
- Disabling a profile affects the next request only.

### V5.1 migration

- `settings.gemini.apiKey` becomes the profile **Gemini — Migrated**, with
  the same model, and becomes the default route if none exists.
- It is verified on disk, then the old field is cleared.
- It is deduplicated by key, so it is idempotent. It never touches the
  network.
- Old fields left unused: `settings.gemini.modelId` and `keyRevision`, and
  the `correctly.v5.connection` key.

## Usage/billing behavior

- **Reservation:**
  - The global daily attempt is reserved, with its route and operation ID,
    before any send.
  - If the route changed meanwhile, the slot is released and nothing is
    sent.
- **Outcomes:**
  - A parsed answer counts as completed.
  - An HTTP error or an unusable body counts as failed.
  - A timeout, a network loss or a local abort counts as **unknown** (may be
    billed).
  - Requests left pending by a stopped worker become unknown at the next
    start and are never replayed.
- **Retries and fallback:** none. Every retry is a new user action.
- **Free calls:** "Check key" (model list) is free and not counted.
- **Billable test:** "Test" asks first and is counted as task `test`.

## Problems and mitigations

- **Import cycle:** `contracts → providers → settings → rewrite` left a
  constant undefined. Route slots and profile IDs moved to `models.ts`.
- **CSS bug, present since V5.5/V5.6:** `display` rules overrode the `hidden`
  attribute, so the shortcuts "Cancel edit" button showed. Fixed with a
  global `[hidden]` rule.
- **Smoke script:** `--offline` mode sent one dummy request (V5.1 issue).
  Fixed.
- **Stricter Gemini test:** the Gemini connection test now requires a
  complete answer (finish reason STOP), as the tasks already did.
- **Open issue:** the options page could rewrite the old V5.1 key field in a
  tiny race window during migration. The next run clears it again, without
  duplicates.

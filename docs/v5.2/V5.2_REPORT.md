## 1. Summary

- The toolbar button is the minimal V5.2 trigger. Without a key, without
  consent, or on a page Chrome does not let extensions script, it opens the
  settings, as in V5.1. Otherwise it injects `content.js` into the clicked
  tab only (`activeTab` + `scripting`). No keyboard shortcut, context menu or
  floating button: those are V5.3.
- The content script takes an immutable in-memory snapshot of the selection
  and sends only the selected text to the worker. The worker makes **one**
  Gemini request that both detects and corrects errors.
- The model reply is validated strictly. The page shows "No corrections
  needed", or Original/Corrected with **Apply**, **Copy** and **Cancel**,
  then **Undo correction** after Apply.
- Apply replaces the exact range in `textarea` and `input[type=text]` only,
  after re-checking the field, its full value, the selection and IME state.
  Everything else is copy-only.
- Correction is opt-in: a new **Correction** consent checkbox in the settings,
  off by default.
- Every correction is counted by the existing V5.1 `UsageGuard` (reserved
  before the request), in the same daily limit as connection tests.

## 3. Model and endpoint

`POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
with the `x-goog-api-key` header, using the model chosen in V5.1 (default
`gemini-3.1-flash-lite`; never changed automatically). The body contains:

- `systemInstruction`: a conservative proofreader that preserves
  language/tone/names/numbers/URLs/abbreviations, never translates or
  formalizes, and ignores instructions inside the text.
- `contents`: the user's text as its own `user` part. Leading and trailing
  whitespace stays local and is put back after correction.
- `generationConfig`: `temperature: 0`, `responseMimeType:
'application/json'`, `maxOutputTokens: 512 + 2 × code points`.

The 30 s timeout has no retry. `responseSchema` is **not** sent: the
GenerationConfig section of the API reference could not be read on
2026-10-15. Only `systemInstruction` and `responseMimeType` were confirmed,
from the samples. The JSON shape is therefore enforced locally.

Validation (`parseCorrection`) rejects the following:

- a reply longer than 4× + 200 characters;
- non-JSON, or JSON wrapped in Markdown fences;
- extra or missing keys, or wrong types (`"true"`, `1`);
- an empty correction;
- output longer than 2× + 50 code points;
- `hasErrors=false` with a changed text;
- a candidate whose `finishReason` is not `STOP` (`MAX_TOKENS`, `SAFETY`…),
  or a blocked prompt.

`hasErrors=true` with an identical text is treated as "no corrections". When
a link, email or number differs between the original and the suggestion, the
suggestion is shown but Apply is disabled.

## 4. Data flow

```text
toolbar click → worker: key + consent? → executeScript(content.js, this tab)
content: capture(snapshot) → sendMessage({type, text})
worker: sender = our content script, top frame; exact shape
      → consent/key/model/online checks → reserve 1 attempt → ONE fetch
      → parse + validate → settle usage → reply (no key, no text stored)
content: re-validate reply → preview (text nodes only, closed shadow root)
Apply → recheck field/value/selection/IME → setRangeText + input event
Undo  → only if the field value is still exactly the applied value (no API call)
```

## 9. Security and privacy

- The key stays in the worker. The content script never receives it, and no
  message carries it (asserted in tests).
- Text is sent only after an explicit click **and** stored consent. Nothing
  runs on install, on page load or while typing (M11 and tests).
- The user's text and suggestions live only in memory. Tests check that
  storage holds no text, and the code contains no logging.
- The suggestion is rendered with `textContent` in a closed shadow root;
  markup is shown as text (P15).
- The worker accepts `CORRECT_TEXT` only from this extension's content script
  in a top frame, with an exact shape and at most 2,000 code points.
- Permissions: `activeTab`, `scripting`, `storage`; host: Gemini only. There
  is no `<all_urls>` and no declared `content_scripts`. The build audit
  enforces this.
- Residual risks:
  - The model can still make wrong or stylistic changes. The preview is the
    safeguard.
  - The protected-token check covers links, emails and numbers only, not
    negations or names.
  - The key is unencrypted in the profile (unchanged from V5.1).
  - The local limit is not a billing limit.

## 10. Limitations and deferred work

- No native Ctrl+Z integration: `setRangeText` is outside the browser undo
  stack. Use **Undo correction** instead.
- Frameworks that ignore `input` events may revert an Apply. This has not
  been verified on real sites.
- The daily limit is shared between tests and corrections. Per-operation caps
  are V5.8.
- Not built: shortcuts, context menu and floating button (V5.3), styles
  (V5.4), translation (V5.5), custom abbreviations (V5.6), providers (V5.7),
  caps and alerts (V5.8), statistics (V5.9).

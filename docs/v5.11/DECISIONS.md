# Correctly V5.11 — Implementation decisions

Owner-approved decisions (spec §1) are implemented as written. The items
below are **engineering choices** the spec left open (Appendix C). Each one
is for owner review; none overrides an approved decision.

| #   | Topic                               | Choice                                                                                                                                                                                                                          | Why                                                                                                                                                              |
| --- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Handle setting                      | The existing V5.3 `triggers.smartButton` toggle now shows the right-edge handle (label renamed in the settings). No new toggle, no migration.                                                                                   | Spec §15: reuse the existing visibility preference; avoids contradictory toggles. Same all-sites permission flow.                                                |
| D2  | Handle position                     | One **global** `yRatio` (0–1, default 0.5) in a new key `correctly.v5.handle`, written **only by the worker** on `HANDLE_POSITION`. Read back through `PAGE_CONFIG`.                                                            | Content scripts cannot read `storage.local` (TRUSTED_CONTEXTS since V5.7). Global, not per site: conservative default from spec §2.4 (assumption, not approved). |
| D3  | Sizes                               | Modal `min(640px, 100vw−24px)` × `min(520px, 100dvh−24px)`; handle 48×25 px, hover scale 1.08 / 140 ms, drag threshold 6 px, safe margin 16 px, logo 18 px.                                                                     | Spec §2.2 proposals; checked on screenshots (`evidence/modal-chrome.png`, `evidence/handle-chrome.png`).                                                         |
| D4  | Ctrl+M                              | New command `open-correctly`, suggested `Ctrl+M` (`MacCtrl+M` on macOS). Respects the existing "Keyboard shortcut" setting. Alt+Shift+C still corrects directly.                                                                | Spec §4.2: `chrome.commands`, no page key listener, no `preventDefault()` on pages. A conflict can stop Chrome from assigning it (see Troubleshooting).          |
| D5  | Toolbar icon                        | `action.onClicked` now opens the modal (`intent 'open'`) instead of correcting directly. No popup was ever configured.                                                                                                          | Spec §4.3. Direct correction stays available (Alt+Shift+C, right-click menu).                                                                                    |
| D6  | One open path                       | Handle → `OPEN_MODAL` message → worker `correctInTab(…, 'open')` → inject `content.js` → `openModal()`. Toolbar and Ctrl+M use the same function.                                                                               | One controller, same consent/route gate, same frame logic as the V5.3 smart button.                                                                              |
| D7  | Open gate                           | Without consent, or with no usable route for **any** of the three actions, opening shows the settings page (as the toolbar did before). With at least one route, the modal opens; a tab without a route reports it on Generate. | Keeps V5.2/V5.7 behaviour; never opens a modal that cannot do anything.                                                                                          |
| D8  | Context menu & per-action shortcuts | Kept, with the V5.2–V5.5 panel. They are not one of the three modal entry points.                                                                                                                                               | Spec says "never silently delete functionality" and does not list them as modal triggers. Opening a modal on Correction from "Rewrite…" would be contradictory.  |
| D9  | Non-editable page text              | Not prefilled (empty input + the V5.2 notice). Contenteditable / rich editors: prefilled, Apply disabled (copy-only).                                                                                                           | V5.2 rule "plain page text is never sent" and sensitive-field exclusions are kept (spec §11.3: do not bypass existing exclusions).                               |
| D10 | Edited shared text                  | Apply still targets the verified **original** selection, guarded by `applyBlocker` (same field, value and range, no IME). Never a destination inferred from text equality.                                                      | Spec §11.2.                                                                                                                                                      |
| D11 | Option change after a result        | Clears **that tab's** result (other tabs untouched).                                                                                                                                                                            | Spec §8/§9: never show an old result as matching new options.                                                                                                    |
| D12 | Cancel                              | Footer Cancel discards the active tab's result or waiting request (the late reply is ignored; it may still be billed and is said so). Hide ends the session.                                                                    | Spec §10.3.                                                                                                                                                      |
| D13 | Escape                              | Keyboard equivalent of **Hide**. No visible X.                                                                                                                                                                                  | Spec §14.3.                                                                                                                                                      |
| D14 | Settings gear                       | Sends `OPEN_SETTINGS`; the worker calls `chrome.runtime.openOptionsPage()`. The modal stays open.                                                                                                                               | Content scripts cannot open the options page themselves; spec §5.2.                                                                                              |
| D15 | Scrim                               | A light non-clickable scrim behind the modal (`aria-modal="true"`, focus kept inside). Clicking it does nothing.                                                                                                                | A modal dialog; prevents moving the page selection that Apply relies on.                                                                                         |
| D16 | Page keys                           | `keydown`/`keyup`/`keypress`/`input` from inside the modal stop at its shadow root.                                                                                                                                             | Site shortcuts (e.g. webmail single-key commands) must not fire while typing in the modal.                                                                       |
| D17 | Frames                              | Handle in the top frame only (as `smart.js` was). Toolbar and Ctrl+M open in frame 0. A selection inside an iframe is not captured from there: empty input.                                                                     | Spec §13.2: no guessed cross-frame ranges.                                                                                                                       |
| D18 | Removed messages                    | `correctly.v5.openRewrite` / `openTranslate` (smart button only) are removed; the worker ignores them.                                                                                                                          | Smaller attack surface; their features live in the tabs.                                                                                                         |
| D19 | Version                             | 5.11.0 / "Correctly V5.11" (manifest, package, lockfile, audit, ZIP name).                                                                                                                                                      | Milestone convention.                                                                                                                                            |

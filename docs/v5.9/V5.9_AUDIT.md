## Decisions

### Single source of truth

The V5.8 `operations` journal is the only source of the statistics: one
record per request, counted at "marked sent", with its route, outcome and
tokens.

- There is no second counter and no separate projection that could double
  count or drift.
- Statistics read it and never write quota stores.

### Schema v2 (additions only)

- an index `dispatchAt` (send time);
- an `events` store (Apply/Undo);
- a `prices` store (owner price references).

### Retention

Operation retention moves from 90 to **400 days**, which covers a full
366-day custom range. Counters are unchanged.

### Apply / Undo events

- Replies carry the opaque operation ID.
- The page reports an edit only after the field really holds the new text.
- The worker accepts it only for a completed request of the same tab and
  frame, once per action.

### Prices

Official list prices for the five reviewed models were checked on
2026-10-15:

- Google: page "Last updated 2026-10-15 UTC";
- OpenAI: `developers.openai.com/api/docs/pricing`.

The owner can add dated references. All estimates are exact integers
(pico-dollars).

### UI scope

- No chart library: a CSS bar chart with an equivalent table.
- English only, like the rest of the UI.

## Gaps (cannot be reconstructed)

- **Days before the V5.8 upgrade** (2026-10-15 for this owner). They exist
  only as V5.8 counters, without operations, tokens or models. Statistics
  start at the V5.8 upgrade and say so.
- **V5.8 operations:**
  - their cached-token count is unknown, so all input is priced at the
    normal rate;
  - they have no origin tab, so no Apply event can be recorded for them.
- **Native Ctrl+Z.** It cannot be observed; only Correctly's own Undo button
  is recorded.

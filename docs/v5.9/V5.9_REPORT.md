## Metric definitions (one source, no double counting)

### Source and placement

- **Source**: the V5.8 `operations` journal, one record per request.
- A request is placed at its **send time** (`dispatchAt`): the instant V5.8
  counted it. An edit is placed at its own time.

### Counts

- **Requests used**: operations in `dispatching`, `completed`,
  `failed-after-send` or `unknown`. This is exactly the V5.8 counted set.
  Reservations are shown separately as "in progress".
- **Successful**: `completed` (a validated result, "no errors found"
  included).
- **Failed**: `failed-after-send`.
- **Answer lost**: `unknown`.
- **Waiting**: `dispatching`.
- **AI edits applied** / **Undos recorded by Correctly**: confirmed events,
  at most one of each per request; an Undo needs its Apply.

### Tokens

- Sums over the requests that reported them, always shown with "N of M
  requests".
- When none were reported, the page says **Not reported**, never 0.

### Cost

- Priced only when input **and** output tokens are known and a price is in
  force at send time.
- States, shown with the number of requests each covers:
  - **Complete**: every request priced;
  - **Partial**: some priced;
  - **Unavailable**: none priced;
  - **$0.00**: only when no request was sent.

### Groups

- The action, provider, model and key groups are disjoint and add up to the
  total (tested).
- A deleted key shows as `Deleted key (…1234)`.

### How prices are applied

- **Thinking and reasoning tokens** are already counted in the reported
  output, and billed as output by both providers.
- **Cached input** is a subset of input. It is priced at the cached rate when
  its count is known; otherwise all input is priced at the normal rate.
- **Owner references** are added, never edited. Each one applies from its
  date, so older requests keep their price.
- **Coverage of the official references.** They apply to every recorded
  request: the journal only starts at V5.8, on 2026-10-15.

## Not run, not covered, limitations

- **Manual checklist: NOT RUN** (owner, Chrome and Brave).
- **Live calls with real keys: BLOCKED** (owner keys and approval needed). No
  real token counts or real estimates have been observed in a browser; they
  are covered with fixtures.
- **History before the V5.8 upgrade.** It exists only as limit counters, so
  Statistics start at the V5.8 upgrade and the page says so.
- **V5.8-era requests:**
  - their cached count is unknown, so all input is priced at the normal
    rate;
  - they have no origin, so no Apply event can be recorded for them.
- **Edits outside Correctly.** Native Ctrl+Z and edits in contenteditable
  editors (copy-only) are not observable. Only Correctly's Apply and Undo
  count.
- **Not implemented:**
  - hourly view of Today (one daily bar);
  - "net edits" metric;
  - "blocked locally" series (optional in the spec);
  - EUR conversion (USD only);
  - French UI (the extension UI is English only);
  - import of statistics (out of scope);
  - popup (Correctly has none).
- **Deletion.** It removes finished requests and edit events before a date.
  Limit counters, alerts and requests in progress are kept, so limits stay
  enforced (tested with a limit of 1).
  - The facts themselves are deleted, so nothing can regenerate the deleted
    history.
  - A deletion note is kept and shown.
- **Price freshness.** Official prices can change after 2026-10-15. The page
  shows the check date.
- **Not tested:** a two-window settings race on the price form in a real
  browser (references are add-only with unique IDs).

## Architecture

```text
settings page ──(Web Lock, read→change→write→read back)──► correctly.v5.shortcuts
                                   (V4 key correctly.shortcuts.v1: read once, never written)
worker  PAGE_CONFIG → {smartButton, enabled [trigger,replacement] pairs}   (no settings, no key)
smart.js (opt-in page script) → ShortcutExpander: trusted insertText + separator
        → exact range check → execCommand('insertText') (native undo) | setRangeText
worker  correct / rewrite / translate → shield(selected text): protected spans → [[RANDOM_n]]
        → ONE Gemini call → every placeholder exactly once → restore → preview
```

## Behavior and safety

- **Expansion is local only:**
  - It makes zero network calls and uses no quota (unit test, C05).
  - Synthetic, paste, drop, undo, IME and multi-character inputs never expand.
  - Password, email, OTP, payment, read-only, Monaco/CodeMirror and rich
    editors are never touched.
  - The separator is kept exactly once, and the caret ends after it.
- **Native undo:** expansion uses `insertText`, so Ctrl+Z restores the
  trigger. `setRangeText` plus an `input` event is the fallback.
- **Off by default:** the feature needs all-sites access, requested when the
  user turns it on. Migrated V4 data therefore starts with expansion off.
- **Writes:**
  - Writes are serialized across settings tabs and read back to verify.
  - Independent edits merge.
  - A stale edit or delete fails with a message instead of overwriting.
  - A damaged store is reported and never overwritten.
  - `chrome.storage` has no compare-and-swap; the settings page is the only
    writer.
- **Backup:**
  - The export contains shortcut fields only. Tests check that the key,
    settings and usage data are absent.
  - The import validates the whole file in memory and shows a preview
    without writing.
  - Policies: keep mine (default), overwrite (keeps the local ID), replace
    all (asks for an extra confirmation).
  - The import is refused if the store changed since the preview. Re-importing
    the same file is a no-op.
- **AI protection:**
  - Only the shortcuts found in the selected text are masked. The dictionary
    is never sent.
  - Placeholders use 6 random characters (`crypto.getRandomValues`), with a
    new namespace if the source already contains the prefix.
  - Each candidate must keep each placeholder exactly once and must not invent
    or alter one; otherwise it is rejected.
  - A request with protection is still one request.

**C05** uses real trusted typing over CDP. It checks that:

**Bug found and fixed by the tests:** without Web Locks, two simultaneous
writes could overwrite each other. Writes are now serialized in-page as well.

Matcher performance: 1,000 lookups on a 50,000-character field with 500
shortcuts finish in well under 1 s (unit test). There is no separate
p50/p95 benchmark.

## Known limitations

- Expansion works only in `textarea` and `input[type=text]`, not in Gmail or
  Notion style editors, as in V4.
- Open tabs need a reload after turning shortcuts on.
- Dictionary changes reach a page when the user refocuses a field or returns
  to the tab.
- Case folding is `toLowerCase()`; the Turkish dotted/dotless I is not
  special-cased.
- No "Undo Correctly expansion" button: native Ctrl+Z covers it where the
  browser supports `insertText`.
- The smoke script's `--offline` mode still sends one dummy-key request at
  step M9 (issue carried over from V5.1).

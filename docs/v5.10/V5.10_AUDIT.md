| Area                   | Module(s)                                                             | Trust zone                     | Tests                                                           |
| ---------------------- | --------------------------------------------------------------------- | ------------------------------ | --------------------------------------------------------------- |
| Manifest / permissions | `frontend/manifest.json`, `scripts/audit-dist.mjs`                    | browser                        | `audit-dist.test.ts`, build audit                               |
| Message gateway        | `background/index.ts` (`isTrustedSender`, `isContentScriptSender`)    | trusted worker                 | `service-worker.test.ts`                                        |
| Request dispatch       | `background/connection-controller.ts` (`begin` → `dispatch`)          | trusted worker                 | `connection-controller`, `routing`, `release-v510`              |

| Shortcuts              | `shared/shortcuts.ts`, `content/shortcuts.ts`, `shared/protection.ts` | page + settings                | `shortcuts`, `shortcut-expansion`, `shortcuts-ui`, `protection` |
| Real-browser harness   | `scripts/verify-browser.mjs` (CDP, throwaway profiles)                | tests                          | 23 steps                                                        |

**Paid paths.** One `fetch` call site (`transport.requestJson`). It is
reached only through `ADAPTERS[provider].generate` (from
`ConnectionController.dispatch`, after `begin`) or `listModels` (free key
check, never counted). `begin` runs consent → route → online → `admit`
(atomic, IndexedDB) → route re-check → `dispatch` (marked sent, limits
re-checked) **before** the network call. No retry anywhere, no fallback.

## 4. Security audit

| Threat                               | Finding                                                                                                                                                                     |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Key reaches a page or content script | None. Keys are read only in the worker (`resolveRoute`, `runKeyCheck`); replies are rebuilt field by field. Tested: KEY-21, KEY-27, browser M5a/L3/M15                      |
| Forged messages                      | Strict exact-key shapes. Settings-only actions need an extension-page URL; a content script cannot test, check keys, fetch a URL, reset usage or write storage (V5.10 test) |
| Web page → extension                 | No `externally_connectable`, no `web_accessible_resources`, no window `message` listener in content scripts                                                                 |
| Arbitrary URL / redirect             | Fixed origins per adapter, `redirect:'error'`, `credentials:'omit'`, `no-referrer`; CSP `connect-src` = the two APIs                                                        |
| Remote code                          | None: CSP `script-src 'self'`; no `eval`/`new Function`/`innerHTML` in `src` or `dist`; no source maps; no `console` in `dist`                                              |
| Prompt injection                     | Instructions and text are separate parts; output is strictly parsed then rendered with `textContent` (V5.10 test SEC-009 on both providers)                                 |
| Provider error text                  | Never shown: fixed copy per code (V5.10 test with a key-like token in the error body)                                                                                       |
| Prototype pollution                  | IDs gated by `/^[A-Za-z0-9-]{8,64}$/`, policy needs plain records, shortcuts use `Map`                                                                                      |
| CSV injection                        | `csvCell` neutralizes `= + - @ \t \r \| %`, also after leading spaces                                                                                                       |
| Supply chain                         | `npm audit`: 0 vulnerabilities; no runtime dependency; only install script: `esbuild` (dev)                                                                                 |
| Shipped artifact                     | Extracted ZIP = `dist/` byte for byte; no sentinel key, `.env`, private key, source map, `.exe`, Java, Python, localhost or port 8081                                       |

### Residual risks (not fixed, documented)

- **R-1 (P3) Overlay clickjacking of the smart button.** A hostile page can
  hide the button under a transparent layer. A trusted click then sends the
  user's own selected text to the user's own provider (one request, counted).
  No key or other data leaks. Mitigation: the smart button is opt-in.
- **R-2 (P3) Response size.** A response body is read in full before the
  256 KB limit is checked. Only the two provider origins can answer.
- **R-3 Local profile.** Keys sit unencrypted in the browser profile. Malware,
  another malicious extension or someone with access to the device can read
  them. Requests are capped by count, not by money.
- **R-4 Read-only fields.** An explicit trigger on a read-only text box still
  sends the selection for a copy-only suggestion (V5.2 contract). The smart
  button is never shown there.
